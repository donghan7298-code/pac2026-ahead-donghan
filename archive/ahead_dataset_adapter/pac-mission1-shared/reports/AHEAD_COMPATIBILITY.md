# AHEAD 생성기 연결 검증 결과

검증일: 2026-10-07. 실행 환경: Python 3.12.14, NumPy, PyYAML, pytest 8.4.2.
Python 3.10 문법 호환성은 AST 검사로 확인했고, Python 3.10/ROS2 실환경 실행은 미실시.

## 결론

생성기의 학습·평가용 박스 데이터를 기존 플래너에 연결할 수 있다.
추가한 JSON 어댑터와 `experiment --ahead-dataset` 경로로 기존 실험용 박스 생성기를
우회한다. 특징 추출·후보 평가·미래 시나리오·가상 적재·teacher 라벨·모델 학습까지
실행했다. GitHub 원격 변경은 이 작업에서 수행하지 않았다.

## 검증 항목

| 검증 | 결과 |
|---|---|
| 생성기 원본 테스트 | 4 passed |
| 플래너 전체 테스트 | 55 passed: 기존 36 + 추가 19 |
| 기본 생성 설정 | 6개 시나리오, 144개 박스 관측 모두 파싱·검증 |
| 시나리오별 앞 3회 계획 | normal 3, size_mixed 3, weight_mixed 2, late_large 3, late_heavy 3, repeated_sku 3개 가상 적재 |
| 미래 시나리오 | 유효한 계획마다 7개 공통 시나리오 평가 |
| 재학습 CLI | train 2 / val 1 / test 1, 3 epochs, 데이터 집계 1회, 시나리오당 2단계 실행 |
| 재학습 후 비교 경로 | greedy/current/teacher/ranking/ahead 각각 평가용 2개 박스 배치 |
| 기존 생성기 사용 여부 | 외부 경로에서 make_episode 호출 시 실패하도록 한 테스트 통과 |
| 정답 유입 방지 | ground_truth 없이 동작하고, 잘못된 ground_truth 파일을 추가해도 입력에 사용하지 않음 |
| 재고 관리 | 관측 시 1회 차감, 가상 적재 시 중복 차감 방지 |
| 기존 모델 | 새 데이터 계약이 없으면 OOD fallback |

S0003의 3번째 박스는 입력 변환에는 성공했지만 유효 후보가 0개였다.
참조 검색의 후보 46개에 OUT_OF_BOUND 20, BOX_COLLISION 14,
APPROACH_FAIL 14, LOW_SUPPORT 12 판정이 있었다. 한 후보에 여러 코드가 있을 수 있다.
이는 제한된 reference backend의 계획 결과이며, 전체 공간에 배치할 방법이
전혀 없다는 증명이나 어댑터 오류로 해석하지 않는다.

## 현재 설정의 한계

- 높이: 팔레트 적재 면 위 1.5m로 해석. 바닥 기준이면 설정을 floor로 바꾼다.
- 팔레트 최대 하중: 원본 null을 보완한 시뮬레이션 가정 150kg.
- 박스 상부 강도: 정보가 없으므로 0N. 다층 적재 평가 전에 팀 강도 기준이 필요하다.
- 미관측 개별 무게: 최대 30kg 상한 사용. 실제 확률분포 모델과 동일하지 않다.
- 관측: identity만 지원. 현재 박스 무게는 생성값 보존, CCTV 잡음/미리보기 미반영.
- 학습 확인은 작은 smoke run이다. 나온 모델은 연결 검증용이고 배포 모델로 교체하지 않았다.
- 전체 에피소드 성능, 큰 데이터 학습, 실제 로봇·IK·충돌·LBCP 검증은 포함하지 않는다.

원본 커밋, 설정, 시나리오별 결과와 학습 실행 정보는
`ahead_integration.json`에 기록했다. 실행 방법은
`../docs/ahead_dataset_integration_ko.md`에 있다.
